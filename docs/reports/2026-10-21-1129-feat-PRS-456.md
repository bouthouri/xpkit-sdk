**Ticket:** PRS-456. Picked by direct order from Jibril (Oussama approved 2026-10-21), first of PRS-456, PRS-506, PRS-457.

## Plan and what changed
- Root becomes a bun-workspaces monorepo (`packages/*`, `examples/*`), `tsconfig.base.json`, one `bun.lock`.
- `packages/core` = F1/F2 core from the xpkit PR #20 branch (`packages/xpkit-core`: schema, parseConfig, createEngine, achievements) + the platform-free runtime from #20 `packages/xpkit-runtime` (evolved `new-xpkit-core`): configureXPKit, achievements and onboarding stores (zustand vanilla), parseOnboardingConfig, assets, fixtures. #21 had no core changes vs its base.
- Dropped: duplicate schema re-export, web/native renderers, playground, vite, notImplemented stubs. Old `examples/` moved to `docs/reference/examples/`.
- Build: tsc NodeNext, explicit `.js` imports (fixes PRS-472), `.d.ts` emitted.

## Decisions
- decided: one `StorageAdapter` (get/set/remove, sync or async). Sync storage loads at creation; async storage starts empty, queues events, applies them after hydration, `engine.ready` resolves then. Stores adapt it with `toStateStorage`.
- decided: corrupt stored JSON starts from the empty state (the ported engine had a `try` without `catch`).
- decided: fixtures exported as raw JSON (`@xpkit-dev/core/fixtures/*.json`); mp4 assets stay in the repo, not published.
- decided: renderers deleted here; PRS-457 restores the native ones from history into `packages/react-native`.
- decided: `parseConfig` errors include the field path (`onboarding.screens.0.id: Required`).
- Docs prose in `docs/01..05` is still intern-scaffold text (only links fixed): follow-up ticket.
